# Evidence report contract

After each experiment, run `bash scripts/report.sh A` or `B`. The generated `reports/<run>/report.md`, `result.json`, `candidate.patch`, and `evidence.zip` record the pinned baseline, candidate commit, changed file count, genuine verification exit codes, patch, and available evidence. The ZIP includes fixed check logs and only explicitly referenced participant evidence. It rejects common credential patterns, external symlinks, nested ZIPs, and oversized files; review it before sharing. If a rerun changes the package, the earlier ZIP is preserved by content hash in the same run directory. Copy `experiments/observations.template.json` to `reports/<run>/observations.json` to add participant-observed model/provider, agent outcome, UTC setup and agent timestamps, tool calls, and token data. Referenced evidence files must be placed in the same run directory. Setup and agent durations are calculated separately. Missing measurements remain **NOT_AVAILABLE**.

The report script never declares that Copilot ran or fixed Django without participant-supplied evidence. Attach the actual Copilot conversation/export or leave `agent_execution_status` as `NOT_OBSERVED`. Record human interventions and a concise patch review. Keep A and B reports separate. A passing command is one part of verification, not proof that the agent's full task is complete. Run `python3 scripts/results.py compare` after both reports; it writes `reports/comparison.md` and `comparison.json`. The token formula runs only when both verified outcomes pass and totals have attached provider reports and matching task, model, mode, runtime, and verification checks. Different or failed outcomes remain visible, without an efficiency percentage. One comparison is exploratory, not statistically conclusive.
